# Contributing

Keep reader setup portable and macOS-first. Changes to the source do not deploy to a running Brain. Use isolated fictional files/state, never a contributor's real notes, queue, email account or scheduler as a test fixture. Preserve project/revision/path guards, approval boundaries, immutable source history and interrupted-archive recovery.

Run the README tests, `scripts/check_release.py` and the isolated demo in a fresh helper environment. Rebuild the standalone handoff from maintained sources; do not hand-edit a generated copy. For new harness/provider/scheduler routes, distinguish instructions from actual end-to-end evidence and add a reproducible acceptance check. Do not claim Windows or Linux desktop support based on helper tests alone.

Before proposing a release, inspect the diff and Git history for credentials, live notes/state, private paths, account/chat IDs and author-specific approvals. Public examples should be fictional. Document material verification limits and current official sources; historical case-study statements must stay dated. Use the MIT licence included here; third-party tools retain their own licences.
